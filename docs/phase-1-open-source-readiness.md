# 一阶段：本地开源发布计划

> 修订日期：2026-08-25
> 产品定位：本地优先的中文表达训练器——可观察表达事实、实时弱提示、场景化可解释报告。

## 1. 一阶段目标

发布 `v0.1.0`，证明同一套中文表达分析核心能够稳定服务以下三个场景：

- 模拟面试
- 工作汇报
- 演讲训练

三个场景共享收音、转写、个人基线、实时反馈、事实分析和数据存储；场景差异只进入阶段流程、语义评价标准与报告建议。

一期成功不以功能数量衡量，而以四个结果衡量：

1. 三个场景都能完成“校准—训练—报告”的完整闭环。
2. 报告中的每个结论都能追溯到文本、声音信号或明确的场景标准。
3. 全新用户能够在几分钟内理解项目价值，并通过示例模式看到结果。
4. 项目以本地自用的合理安全边界公开，不泄露密钥或私人训练数据。

## 2. 工程边界

```text
共享事实层
录音 → 转写 → 个人基线 → 实时提示 → 表达与声音事实 → 持久化
                                              ↓
场景评价层
面试评价 / 工作汇报评价 / 演讲评价
                                              ↓
场景化报告
```

### 共享核心负责

- 录音、ASR、TTS 和会话生命周期
- 个人声音校准及校准状态
- 语速、正文停顿、口癖、重复、长句和实验性声音事实
- 实时弱反馈、错误恢复和数据保存
- 报告的事实部分、评价版本与证据结构

### 场景包负责

- 阶段与角色行为
- 所需材料和配置字段
- 评价维度、权重及语义标准
- 报告建议章节和场景文案

新增或修改场景不得复制共享核心实现。

## 3. 工作包与顺序

### A. 评价可信度与核心边界

- [x] 评价维度、权重和评审口径收敛到各自 `ScenarioPack`。
- [x] 共享评分器移除场景判断，只处理确定性表达信号。
- [x] 三个场景使用不同语义评价轴，而不是只更换相同六轴的权重。
- [x] 全部轴缺失时返回“数据不足”，不回落固定 70 分。
- [x] 语速缺少真实发言时长时不生成虚假满分。
- [x] 持久化句子级声音汇总和真实发言时长，供报告复用。
- [x] 报告返回分析版本、评价版本、分数覆盖率和样本状态。
- [x] 将连贯性、节奏和声音状态拆分；不再生成组合“紧张/稳定”评分。
- [ ] 为每条确定性评分补充用户可读的计算依据。

验收：同一份共享事实进入三个场景时事实值一致；语义轴和建议不同；缺数据不造分。

### B. 三场景核心链路可靠性

- [x] 用参数化测试覆盖三个场景的创建、开始、发言保存、阶段流转和报告生成。
- [x] 建立三场景共享核心测试矩阵，核心模块改动时统一运行。
- [ ] 统一外部 AI 请求的超时、取消和错误映射。
- [ ] 收敛无生命周期管理的后台任务，断开连接后正确释放资源。
- [x] 修复 PDF 干净安装、中文字体和 HTML 降级安全问题。
- [x] 移除传统 `.doc` 的错误支持声明，仅保留可实际解析的 PDF、DOCX 和 TXT。

验收：三个场景的核心链路自动化通过；任一 Provider 失败都有普通用户能理解的恢复提示。

### C. 真实录音验证

- [ ] 每个场景准备一组正常表达与刻意问题表达的对比录音。
- [ ] 验证语速、停顿、口癖、重复和声音稳定指标的变化方向。
- [x] 用 24 条真人网络音频和 4 条同文对照记录方法、原始结果、失败案例与人工复核。
- [x] 修复把录音首尾静音计为正文停顿的问题；真人集边界误报降为 0。
- [x] 人工确认“表达不顺畅”和“紧张听感”不是同一维度，声音实验信号退出综合评分。
- [x] 合成语音只用于回归测试，不作为真实用户有效性的证明。
- [x] 未经真人验证的能力不宣传为心理、情绪或自信判断。

验收：公开评测可以复现，宣传文案不超过证据能够支持的范围。

### D. 首次体验与三场景界面

- [x] 首页用一句话说明“分析怎么说，而不只评价说了什么”。
- [x] 三个场景平等展示，各自说明训练目标和输入要求。
- [x] 提供无需 API Key 的示例报告，并明确标注为固定示例数据。
- [ ] 实时页面只保留低干扰、可关闭的弱提示。
- [x] 报告按“可观察事实—场景评价—下一次练习”组织。
- [x] 前端公开路由改为 `/training`，旧 `/interview` 地址保留兼容跳转。
- [x] 修复 360/390px 横向溢出和关键键盘操作；不做无关视觉重写。

验收：首次访问无需配置即可理解核心价值；三个场景在桌面和移动端都没有阻断问题。

### E. 本地开源发布底线

- [x] 默认仅监听 `127.0.0.1`，HTTP 与 WebSocket 只接受受信本地来源。
- [x] 修复 `.env.example`、README、PRD 和真实目录/场景不一致。
- [x] 前端 lint、类型检查和生产构建可执行。
- [x] 后端基础静态检查可执行。
- [x] 升级存在已知风险的生产依赖；`npm audit` 当前为 0。
- [x] GitHub Actions 使用干净依赖安装执行前端 lint、生产构建和后端测试。
- [ ] 用户确认开源许可证；核验评测音频和示例数据的再分发权利。
- [x] README 包含快速开始、演示 GIF、三场景说明、架构图、隐私边界和已知局限。
- [x] 公开前检查 Git 历史中没有密钥、私人数据或不希望公开的作者信息。

验收：全新 macOS/Linux 环境可按 README 启动；默认不暴露到局域网；仓库具备合法使用和贡献的基本条件。

## 4. v0.1.0 发布门槛

- [ ] 三个场景均完成一次真实训练并生成对应报告。
- [x] 共享事实一致，场景评价维度和建议明确不同。
- [x] 无有效数据时不显示默认分或心理状态结论。
- [x] 后端测试、前端类型检查和生产构建全部通过。
- [x] 示例模式无需第三方密钥即可展示完整价值。
- [x] 默认本地访问边界和密钥处理经过回归测试。
- [ ] README、LICENSE、依赖、资产权利和 Git 历史检查完成。
- [ ] 在私有 GitHub 仓库完成一次发布演练后再转为公开。

## 5. 一期明确不做

- 新增第四个训练场景或继续扩展 Provider 数量
- 登录、账号、云端多用户、支付和排行榜
- 为本地自用引入复杂的云端认证体系
- 视频、肢体动作、微表情或心理状态识别
- 全量数据库命名迁移或无收益的技术重写
- Docker、多平台桌面客户端和完整暗色主题
- 为追求视觉效果加入大体积素材或重动画

## 6. 需求过滤规则

任何一期改动必须至少满足一项：

1. 强化共享中文表达分析核心。
2. 让三个场景中的首次体验更快或更可靠。
3. 提高评价证据、数据边界或发布可信度。

不满足以上任一条件的需求不进入一期。
