# 真人网络音频首轮评测

日期：2026-08-23
对象：当前生产路径 `PcmFeatureBuffer`
结论性质：声学管线诊断，不是心理、情绪或表达能力真值

## 样本与复现

- 来源：[Google FLEURS](https://huggingface.co/datasets/google/fleurs) 普通话简体中文测试集，许可证 CC BY 4.0；逐条音频取自 [FluidInference 文件镜像](https://huggingface.co/datasets/FluidInference/fleurs-full/tree/main/cmn_hans_cn)。
- 24 条真人朗读，15 条男声、9 条女声，总时长 253.64 秒；单条 4.74–16.46 秒。
- 人工复核阶段另加入 4 条同文对照音频，专门隔离文本差异；它们不计入上面的首轮 24 条汇总。
- 样本按镜像编号均匀抽取，保留两组同文不同声音频用于直接对比。FLEURS 不提供稳定的说话人 ID，因此不宣称来自 24 位不同说话人。
- 音频位于 Git 忽略目录 `evals/listen/audio/web_fleurs/`；元数据和 SHA-256 见 `web_audio_manifest.json`。
- 复现命令：`.venv/bin/python evals/eval_web_audio.py`；加入同文对照使用 `--include-controls`。

## 关键发现

### 1. 停顿统计把录音边界当成表达停顿

24 条音频的开头和结尾都各有一段超过 0.5 秒的静音。修复前算法直接遍历整段音频，因此每条至少多报 2 次长停顿：总计报告 93 次，其中 48 次来自边界，占 51.6%。

这不是数据集特有问题。真实用户也会在按下开始后等待、说完后再点击结束；在计算表达停顿前应先裁掉边界静音，同时保留正文内部停顿。

### 2. 语速结果对边界静音高度敏感

当前报告用整段 PCM 时长作为“真实发言时长”。本批样本原始结果为偏慢 3 条、适中 15 条、偏快 6 条；仅排除首尾静音后变为适中 2 条、偏快 22 条，17 条跨越了等级边界。

去边界后的数值只用于诊断分母问题，不直接作为新的正确答案；`120–220 字/分` 的阈值是否适合真人普通话朗读，还需要用户盲听和更多自发口语重新校准。

### 3. 基频总体可用，少数 jitter 明显失真

男、女两组基频中位数方向合理，流式算法与 `librosa.pyin` 的基频中位绝对差为 11.8 Hz。但三条女声的流式 jitter 显著偏高：

| ID | 当前 jitter | `pyin` 复核 | 倍数 |
|---|---:|---:|---:|
| 0404 | 0.1612 | 0.0288 | 5.6× |
| 0555 | 0.2607 | 0.0605 | 4.3× |
| 0888 | 0.1680 | 0.0683 | 2.5× |

在没有算法置信度或第二提取器一致性检查时，这三条不应转换成“声音不稳”的用户评价。

### 4. 固定峰值比例会被背景噪声带偏

首组真实汇报音频人工复核中，`p03` 明显比 `p04` 流畅，但 `p04` 的背景噪声更大。旧算法以峰值能量的 5% 为静音线，分别报告 `p03` 12 次长/49 次短停顿、`p04` 4 次长/24 次短停顿，排序与听感相反。能量分布检查确认，`p04` 的底噪填充了低能量间隙，导致真实停顿被当作持续发音。

共享提取器现改为在每段对数能量分布上做 Otsu 自适应分割。修复后 `p03` 为 3/24，`p04` 为 11/34，排序与人工听感一致；既有人工确认的 `0085`、`0666` 正文长停顿仍保持 0 次，`0555` 的连贯性信号仍高于同文对照 `0267`。该修复只改善停顿检测，不把口音或背景噪声解释成紧张。

### 5. 真实演讲再次确认流式 jitter 假阳性

第二组单人普通话现场演讲中，人工认为 `p08` 比 `p07` 更流畅、结构更清楚、节奏更舒服；两段语速都大致适中，且都没有明显紧张听感。噪声自适应后的停顿数方向一致：`p07` 为 18 次长/35 次短停顿，`p08` 为 15/25。

声音波动却出现反例：流式 jitter 分别为 0.0472 / 0.1558，看似 `p08` 高约 3.3 倍；独立慢速提取分别为 0.0360 / 0.0387，实际接近，并与人工“均无明显紧张感”一致。这进一步确认流式 jitter 仍可能因基频跟踪跳变产生假阳性，继续只保留为实验事实，不参与综合评分或紧张推断。

## 主观复核优先级

1. `0000` vs `0360`：同一句，当前判断分别为 132.9（适中）和 247.3（偏快）。
2. `0020` vs `0275`：同一句，当前判断分别为 106.9（偏慢）和 203.0（适中）。
3. `0085` 与 `0666`：当前各报告 2 次长停顿，但这 2 次全部在录音首尾。
4. `0404`、`0555`、`0888`：听感是否真的比其他样本明显更抖；若没有，即可确认流式 jitter 的假阳性。

前两组结果为 3 条完全一致、1 条接近但等级边界略宽。感知语速不能简单改成“汉字数 ÷ 去边界后的时长”；下一版应把发音速度、正文停顿密度和节奏分别作为可观察事实，再用真人盲听数据校准最终标签。

停顿人工复核：`0085` 和 `0666` 的系统结果均为 2 次长停顿，人工听感在排除录音首尾后均为 0 次。两条误报与边界静音分析完全一致，确认当前停顿提取器不应把音频边界计入正文停顿。

jitter 人工复核：流式算法认为 `0404` 的 jitter（0.1612）约为 `0110`（0.0470）的 3.4 倍，但人工听感认为 `0110` 更不稳定、存在明显卡顿，并主观感觉更紧张。可观察数据中，`0110` 有 7 次短停顿，`0404` 只有 2 次。该反例说明：

- `0404` 的高 jitter 很可能是跟踪器假阳性，与 `pyin` 复核结果一致；
- 短停顿对整体稳定听感的影响可能高于当前 jitter；
- 产品应分别呈现“声音快速波动”和“说话卡顿”，不得将任一单信号直接命名为紧张或心理状态。

同文女声对照 `0555` 与 `0267` 进一步确认了维度分离：人工听感认为 `0555` 是表达不顺畅，`0267` 则有紧张听感，二者不是同一个维度。当前算法却让 `0555` 的短停顿和 jitter 同时更高，无法表达这种差异。因此正式模型应采用以下共享事实层：

1. **连贯性**：短停顿、重复、口癖、重启等表达过程信号；
2. **声音状态变化**：只报告相对个人基线的音高和快速波动变化，不推断心理状态；
3. **语速与节奏**：发音速度、正文停顿与边界等待分别计量；
4. 场景评价层再按面试、演讲、汇报的不同目标解释这些事实，不复用单一“紧张度”。

## 修复回归

根据人工复核结果，已在共享 PCM 和离线声学提取器中排除录音首尾静音。24 条真人音频重新运行后：

- 长停顿先因排除边界由 93 次降至 45 次，再因噪声自适应分割降为 18 次；后一步改善了真实汇报反例的排序，但不把 18 次声明为完整人工真值；
- 与独立边界分析逐条完全一致，残留边界误报为 0；
- `0085`、`0666` 均由 2 次修正为 0 次，与人工听感一致；
- 语速仍保留首轮人工复核表现较好的原口径，没有采用与听感冲突的简单裁边语速。

同时，三场景共享报告已删除“声音稳定性/表达稳定性”混合评分轴，改为独立的“表达连贯性”和“语速控制”。快速音高波动仍留作实验事实，但不参与综合评分，也不再被命名为紧张。
